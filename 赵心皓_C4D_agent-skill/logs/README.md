# logs/ 日志说明（证据链索引）

本目录保存**一次完整端到端运行**的原始产物，评分/复现时按下面顺序看即可。

| 文件 | 记录哪一段 | 对应 Level | 关键看点 |
|---|---|---|---|
| `level1_intro.json` | 模型第一次对话：生成一段 SIAS 学校介绍 | Level 1 | `completion_tokens=750`，`wall_time_s=14.1` |
| `level2_locations.json` | 模型按 schema 吐出的周边地点 JSON | Level 2 | `raw_model_json` 是模型原文；`locations` 是解析后的 **8 个地点** |
| `level3_agent_trace.json` | 函数调用 Agent 的完整多步轨迹 | Level 3 | 4 次工具调用、模型自主决策的全过程 |
| `console_run.log` | 终端运行时的完整打印 | 全流程 | 与上面三个文件一一对应 |

## level3 trace 的 4 次工具调用

| 步骤 | 工具 | 入参（模型自主决定） | 返回 |
|---|---|---|---|
| step1 | `search_nearby_locations` | `{"query":"校园地标与周边美食/景点"}` | 8 个地点（名称/类别/坐标/简介） |
| step2 | `get_weather` | `{"lat":34.4,"lon":113.74,"place_name":"新郑美食街"}` | 阴 / 22°C |
| step2 | `get_weather` | `{"lat":34.395,"lon":113.747,"place_name":"附近公园"}` | 阴 / 17°C |
| step2 | `get_weather` | `{"lat":34.4027,"lon":113.7489,"place_name":"郑州西亚斯学院"}` | 晴 / 25°C |
| step3 | ——（无） | 模型输出带表格的中文总结 | 收尾 |

> 说明：`get_weather` 返回里带 `note:"离线演示数据（基于坐标与日期本地生成，非真实气象站观测）"`。
> 这是故意的——本挑战强调**本地离线**，不真的去调气象 API；天气是工具本地按坐标生成的占位值，
> 目的是演示「模型会不会自己决定去调一个工具」，而非真实气象预报。
