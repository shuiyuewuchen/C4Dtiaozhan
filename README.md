# 我在一台 16GB 的 Mac mini 上，让本地大模型自己做了张校园地图

> 一篇可直接发公众号的草稿。配图建议：插入 `output_screenshots/01` 和 `02`。

## 开头

以前想玩大模型，要么联网调 API，要么租显卡。这次我想试试：
**一台普通的 Mac mini M4（16GB），不联网、不花钱，能不能真的跑起一个大模型，还让它自己干活？**

答案是：能。而且它最后真的给我做了一张郑州西亚斯学院（SIAS）的周边地图。

## 我用了什么

- 设备：Mac mini M4 / 16GB / macOS 26.3
- 运行工具：Ollama 0.40.2
- 模型：gemma4:e4b，81 亿参数，nvfp4 量化，约 9.5GB
- 全程在 `127.0.0.1` 本地完成，没有调用任何云端接口

## 它真的会「自己思考」吗？

我只说了一句话：

> 「给我生成一个 SIAS University 周边的地图，包含校园地标和周边好吃的地方，并顺手给其中几个地点补一下天气。」

然后它自己做了三步：

1. 先调用工具去查「校园地标和周边美食/景点」，列出 8 个地点；
2. 又连着调了 3 次天气工具，给美食街、公园、学校补天气；
3. 最后整理成一段带表格的中文介绍。

这就是所谓的 **Agent / 函数调用**——不是我一步步教它，而是它自己决定先做什么、再做什么。

## 速度怎么样？

实测生成 710 个 token 用了 24.4 秒，大约 **每秒 29 个 token**。
对一台 16GB 的小机器来说，这个速度用来写东西、做小工具完全够用。

## 踩过的坑（最有意思的部分）

小模型没那么听话，它输出的 JSON 我连踩两坑：

- 先是把地点数组多套了一层壳；
- 更隐蔽的是，它居然输出了**重复的键**，导致标准解析直接把 8 个地点全吞成空数组。

最后我加了「保留重复键 + 递归提取」的兜底才稳住。
这也说明：**用小模型做产品，工程护栏比模型本身还重要。**

## 结尾

一台 16GB 的小机器，加上一个开源模型，就能离线跑通一个会自己调工具的 Agent。
数据不出本机，不花 API 钱，隐私还安全。这大概就是本地大模型最实在的价值。
